# 每日训练与积分转赠

前台登录后默认进入「每日训练」，后台从「训练题库」维护内容；两者沿用现有账号身份和页面风格。训练独立于正式模拟面试题库，不扣减面试次数、不采集录音、不调用 AI。

## 题库与训练

训练分为「面试篇」「笔试-软件工程篇」「笔试-人工智能篇」，前后台均按篇章筛选。面试篇含数据结构33题、操作系统29题、计算机网络34题、英文翻译31题、英文问答53题。专业课按原始阅读顺序重排可复制参考答案，移除 PDF 的硬换行和空白缩进，按原文段落及项目列表展示，并保留145张逐页原文裁片，支持按需查看及放大；操作系统第8题的原答案为状态转换图，直接提供原文图示，不编写替代答案。英文翻译从原始材料逐段匹配中文译文；英文问答不设置参考答案。

软件工程篇新增116道题，按软件工程基础、需求分析、软件设计、软件测试、项目与配置管理及综合与历年题整理，并提供修正后的示例答案和来源页码；历年回忆缺少的表格、公式及完整程序条件均标为训练改编，不冒充原题，详情见[软件工程题库校订](written-software-curation.md)。旧`c_programming`集合ID保留并改名为「综合与历年题」，已有题目、个人收藏和训练进度继续保留。人工智能篇新增机器学习44题、深度学习69题、大模型45题、Agent与RAG 44题，共202道，含177道整理校订题及25道补充题；来源和修正详见[校订记录](written-ai-curation.md)。另设文献翻译集合57道，含英文选段、重校参考译文、关键词与来源说明，AI篇合计259道，详见[文献翻译校订](written-ai-literature-curation.md)。

先选择篇章，再选择集合、全部可练题／重点回顾、随机训练／顺序复习后，可以输入本轮题数或选择「整个筛选集合」。默认题数来自后台；请求数超过可用题时只安排现有题目，单次数字上限由 `max_round_questions` 配置。全部可练题和整个筛选集合均只包含当前篇章，默认包括启用公开题及本人私人题，无需先收藏或提交审核，其他人的私人题始终不可见。随机模式按掌握权重无放回抽取，一轮不重复；整个集合模式覆盖筛选内全部题目，随机权重影响顺序。顺序模式按集合与题目固定顺序，完成一道才推进个人位置，每个篇章、集合和来源分别记进度，面试篇保留原有游标键。指定数量时到末尾结束本轮，下轮从头开始；整个集合时从当前位置循环一遍，每题一次。刷新或离开后可以继续当前轮次，也可结束本轮再更换筛选。

专业课与翻译先展示题干，点击查看参考答案后自行标记「还需练习」或「已掌握」。英文问答仅题目和完成按钮。自评不会自动判断正误，也不自动加入重点回顾；使用星标手动收藏。「还需练习」与「已掌握」会保存为用户/题目独立的长期掌握记录，并记录自评次数和最后自评时间，以最近一次有效自评为准。后续随机训练按还需练习/未自评/已掌握默认4/2/1的相对权重抽题；这是相对权重，不是每题固定概率，且不改变已开始轮次的卡片。顺序模式不受权重影响。英文问答的「完成本题」仅记录完成，不推断掌握状态。首页显示本人可访问题目的掌握统计，卡片和收藏列表显示自己的掌握标记。停用、撤回或失去访问权限的题目不再参与抽题，已有训练轮次中的内容会被隐藏，可以跳过且不计当日题数。

## 每日目标与奖励

默认以北京时间自然日计算。当日完成5道不同题后可点击签到，同一道题重复训练只计一次；各篇章、科目跨轮次累加。已完成题数按完成时的日期记录。每日目标在当日首次开始训练时保存快照，后台随后调目标不会影响该用户当天目标。

每天只能签到一次。昨天已签到则连续天数加1，否则从1开始；无补签。连续第N天且N为7的倍数时新增N/7积分，例如7天得1积分、14天再得2积分、21天再得3积分，前21天共6积分。断签不会扣回已获积分，下一轮连续满7天可以重新获得1积分。管理员可打卡但不领取积分奖励，前端不返回内部特殊额度。

签到、连续天数与积分账本变更在一个SQLite写事务完成，数据库按用户/日期及奖励关联去重。普通用户奖励写入积分账本`points_ledger.kind=checkin_reward`，与历史面试次数账本及卡密消费金额分离。

## 私人题与投稿审核

「我的题目」支持新增、编辑、删除和JSON批量导入。先选篇章，再选其下启用集合；专业课、笔试和翻译可填写参考答案，口语仅英文题干。英文集合题干必须英文。批量导入提供模板、逐条预览与错误提示，全部校验通过再整批保存，不产生部分成功。

新增题默认为`visibility=private,review_status=draft`。用户主动提交后变为`pending`但仍不公开；管理员通过后成为`public/approved`。驳回保留私人状态和具体意见；用户可编辑并重新提交，也可主动撤回待审稿。

编辑公开题需要确认：保存后暂转私人并重新审核，旧公开版本立即从他人抽题范围移除。所有编辑、审核与启停操作校验版本号，防止管理员审批已被作者修改的内容。后台只显示公开题及明确提交的待审稿，不浏览未提交草稿。普通管理员只能审核普通用户投稿，超级管理员管理全部可审内容。

后台可以新增官方公开训练题、编辑官方题和答案、停用公开题、启停集合、修改每日目标和默认每轮题数、分页查看打卡奖励。公开投稿与官方题没有自动同步到正式面试题库。

## 配置与数据

`config.toml`的`[training]`集中管理：`timezone`默认`Asia/Shanghai`、`daily_goal=5`、`round_size=5`、`weight_again=4`、`weight_unseen=2`、`weight_known=1`、`max_round_questions=10000`、`max_import_items=100`、`max_import_bytes=1048576`、`max_question_chars=12000`、`max_answer_chars=60000`。每日目标与默认每轮题数在数据库初始化后由后台管理，配置值只用于初始设置；其余部署限制及权重每次从配置读取；权重必须满足还需练习 > 未自评 > 已掌握，且均为正整数。单批导入JSON格式见页面下载模板，不支持将任意PDF直接上传自动解析。

运行数据使用SQLite，`app/assets/training/catalog.json`与`written-ai.json`为初始资料，不是实时题库。启动迁移按稳定`source_key`导入缺失题目，重复启动不重复插入，也不会覆盖后台校订内容。重新整理原始资料可运行：

```sh
.venv/bin/python scripts/extract_training_bank.py --downloads /path/to/source-pdfs --translations /path/to/paired-text.txt
```

抽取脚本按原文大标题和原题号核对，保留必要跨页文本与原文裁片；脚本重新生成初始素材，不覆盖已有数据库内容。详细映射见[来源核对](training-source-audit.md)。

数据库版本16新增训练表，版本17新增转赠表，版本18按旧答案的 SHA-256 摘要修复专业课题库及训练快照的断行与顺序，仅匹配原始答案时更新，不覆盖人工修订或私人题；版本19新增个人掌握表，并按历史已完成卡片回填最新自评和累计次数，重复提交不重复记账，删除账号级联清除掌握记录；版本20为集合和训练轮次新增`section_id`，旧内容归面试篇，新增C集合和四个人工智能集合，幂等导入202道校订题，不改旧题ID、收藏、自评或面试篇顺序游标；版本21新增独立文献翻译集合，一次性导入57道，不覆盖既有题目和学习记录，日常管理以数据库为准；原有版本15的完整公开样例迁移继续保留。升级前停止服务并备份SQLite数据库及对应密码加密密钥，启动后事务迁移；回退需恢复配套备份。账号删除会清理个人练习、收藏和签到，移除私人题正文；已公开贡献保留并去除账号关联。其余用户的训练快照在失去题目权限后不再向其返回。

## 积分转赠

普通用户在个人主页输入接收人的完整登录用户名（不是显示昵称或邮箱前缀）和正整数积分，确认后转赠。接收人必须为启用的普通用户，不允许转给自己。赠出积分不超过发送方当时余额；管理员无需使用此功能。

发送方扣积分、接收方加积分、双方账本和转赠收据在同一写事务提交。前端为每笔请求保留重试标识，遇到网络错误再次提交相同内容不会重复扣分；同一标识搭配不同内容会被拒绝。成功后不可撤回，页面先明确确认接收人与积分。转赠不产生消费金额，不等同于卡密兑换。

双方主页分页展示转出或转入、对方当时的用户名、积分与时间，不能查看不相关用户的转赠记录。任意一方改名不会改变当时收据，删除一方账号也不撤销已完成转赠，另一方仍可查看自己相关记录。`points_ledger`分别记录`transfer_out`与`transfer_in`，引用同一笔转赠ID。

## 验证

针对训练素材、访问隔离、审核版本、进度恢复、顺序末尾、收藏小题库、跨日、7/14/21奖励、并发去重、失败回滚、删除账号及转赠运行：

```sh
.venv/bin/python -m pytest tests/test_training_assets.py tests/test_training.py tests/test_training_mastery.py tests/test_training_sections.py tests/test_credit_transfers.py -q
```

浏览器验证使用独立8003端口和隔离数据库，不向正式账号写入测试题目、签到或转赠。真实SMTP及AI均不参与这些检查。
