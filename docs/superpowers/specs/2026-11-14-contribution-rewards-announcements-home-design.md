# 题库贡献奖励、公告与备考首页设计

## 目标

鼓励用户提交高质量题目，并在管理员审核通过后发放模拟面试次数；为管理员提供可发布、下架的图文公告管理；将《2027 川大计算机复试·内部通关白皮书》的内容整理为登录后的默认备考首页。实现沿用项目现有 FastAPI、SQLite、服务层、次数账本和静态页面。

## 当前状态

- 用户题目保存在 `training_questions`，投稿先为私人题目，提交后进入 `pending`，管理员批准后变为公开题目。
- 面试次数通过 `credit_ledger` 记录；每日训练连续签到已有独立奖励表和事务发放逻辑。
- 登录后的默认视图是每日训练，登录页目前承担访客介绍和登录入口。
- 系统没有通用公告内容模型或公告图像上传接口。训练题图片按受控资源路径访问，可参考其访问控制和路径校验。
- 白皮书为 8 页，涵盖备考战略、深度学习和数学基础、LLM、论文与项目实践、软件工程笔试、机试、AI 笔试与文献翻译、面试流程、导师及录播课程。PDF 中包含飞书、微信和 B 站链接及星级重要性；旧模拟面试站明确标注已下线。部分项目、课程内容仅对购买套餐的用户开放。

## 方案选择

1. 将功能拆成题目奖励、公告管理、备考首页三个模块，复用现有系统。公告和奖励配置进入 SQLite；公告图片受控上传；静态白皮书资源目录以版本化 JSON 随代码维护。推荐此方案，数据权限、事务和运营操作统一在现有后台中。
2. 将公告和奖励配置保存在 JSON/Markdown 文件中。文件编辑简单，但并发管理、发布状态、操作审计、图片附件及奖励事务难以保证。
3. 接入外部 CMS。内容运营功能成熟，但增加服务部署、账号权限同步、网络依赖与备份职责。

## 题目贡献奖励

### 用户行为

- 用户可以在现有题目投稿和审核流程中继续贡献题目，不增加新的投稿入口。
- 用户主页展示当前奖励规则、当前规则版本的有效进度、累计获得次数和奖励明细；默认公告说明投稿奖励、每日签到奖励、联动小铺购买与卡密兑换、次数转赠。
- 只有管理员批准并公开的普通用户投稿计入奖励。私人草稿、待审、驳回及撤回的题目不计入。

### 管理规则

- 后台配置两个正整数：每 `n` 道题和奖励 `m` 次模拟面试；初始默认 `n=5, m=1`。
- 配置修改创建新的规则版本，仅统计新版本生效后审核通过的题目；不追溯历史投稿，也不扣除已经发放的次数。
- 管理后台可以查看每个规则版本、贡献进度及发放明细。

### 入账与防重复

- 管理员批准题目时，在同一 SQLite 写事务内更新公开状态、创建唯一的贡献计数记录，并按达到的奖励阈值更新用户次数和 `credit_ledger`。
- 贡献记录对题目设置唯一约束，防止重试或重复审核产生多次奖励。奖励流水引用规则版本和阈值序号，便于审计。
- 用户删除题目或后续下架公开题目不撤销已发奖励；避免历史次数账本被追改。管理员需通过正常次数调整流程更正异常奖励。
- 达到多个阈值时按阈值差额一次发放对应次数，事务失败时状态、进度和次数全部回滚。

## 公告管理

### 内容与状态

- 公告包含标题、摘要、有序内容块、状态、创建/更新时间、发布时间及操作者。
- 内容块支持段落、标题、图片和带标题的外链。服务端按字段白名单处理内容，不接受任意 HTML。
- 管理员可创建草稿、编辑、预览、上架和下架公告。发布后立即进入首页公告源；下架后立即从首页隐藏。列表支持状态筛选和标题搜索。
- 首次部署自动创建一条默认上架公告，说明题目投稿奖励、每日签到奖励、联动小铺购买与兑换流程、次数转赠；公告封面使用用户提供的四川大学主题图片。默认公告只能创建一次，不覆盖管理员后续编辑。
- 公告变更保留必要的创建、发布和下架时间以及操作用户，便于后台追踪。

### 图片与链接

- 图片通过管理员授权的上传接口保存为独立公告附件，校验实际文件格式和可配置大小上限；公开公告详情只能访问已关联图片。
- 外链只允许 HTTP/HTTPS，渲染时使用安全的链接属性；禁止通过图片 URL 或 HTML 注入脚本。
- 图片文件名使用服务端生成的不可猜测标识，禁止客户端路径参与存储路径拼接。

## 登录后的备考首页

### 入口和布局

- 首页只对登录用户开放。登录成功后默认打开“备考首页”，不改变现有每日训练、面试、考试和个人主页导航。
- 页面采用与现有系统一致的米白、朱红、浅金、草木绿视觉体系，以清晰的行动入口和可扫描的资源目录为主，不把 PDF 原始长目录整页照搬。
- 页首为最新已上架公告自动轮播。公告项可暂停/手动切换；点击进入完整图文详情，轮播内容少于两条时保持静止。
- 首屏提供每日训练、模拟面试和上机考试入口，并显示简洁的复试阶段路线。
- 后续资源分为“备考路线”“基础与 AI”“笔试与机试”“面试准备”“导师与课程”主题；面试准备按 PPT/自我介绍、专业课问答、英文翻译、英文问答和专家问答组织。
- 白皮书作为导航分类和资源主题参考，不逐条机械复制目录；有星级重要性标记的条目或主题在首页保留优先级信息。
- 站内已有功能优先使用站内跳转；PDF 中有明确 URL 的资料保留原始目标并标记为外部资料。白皮书明确标注购买套餐限制的资源，资源卡片保留访问限制提示。
- 不展示 PDF 标注已下线的旧模拟面试服务器地址，不把只有资料名称而无可用链接的条目伪装为可点击资源。

### 内容维护

- 白皮书资源目录作为版本化 JSON 与代码一同维护，字段包括稳定 ID、分组、标题、说明、优先级/星级、链接类型、目标地址和访问限制提示。
- 公告内容由后台管理，不混入静态首页资源 JSON。
- 资源目录更新需要检查站内路由目标和外部 URL 协议；外链可访问性无法保证时，界面明确标记为 PDF 原始资料链接，不承诺目标服务可用。

## 数据与权限

- 新增奖励规则版本、题目贡献计数/发放关联、公告及公告附件记录；延用现有 `app_settings` 和 `credit_ledger` 模式，必要时增加单调递增的 SQLite schema 版本。
- 普通用户只能读上架公告、其个人投稿进度和其个人奖励记录。
- 管理员可维护公告、图片和奖励规则，并查看投稿奖励统计；管理员自投稿按当前投稿人归属处理，是否参与贡献奖励由现有后台权限规则决定，首版默认不奖励管理员账户。
- 所有奖励数值、权限主体和待审题目归属由服务端从数据库确定，不信任客户端提交的用户 ID 或额度。

## 失败处理

- 奖励阈值配置必须为正整数；非法值在保存时明确拒绝，保留原配置。
- 奖励事务遇到数据库错误时整体回滚，并返回可操作错误；管理员不得看到“已成功”但用户次数未入账的状态。
- 图片格式、大小或存储失败时不发布不完整公告，明确显示失败原因；编辑草稿不应丢失已保存内容。
- 首页公告请求失败时仍可浏览其余备考内容，并显示可重试的公告加载状态；资源 JSON 无法读取属于应用启动/构建错误，不静默生成空资源页。
- 已下架或不存在的公告详情返回明确的不可用页面，不泄露草稿内容。

## 验证计划

- 奖励服务测试：第 `n-1`、`n`、`2n` 道审核通过边界；重复批准/重试只计一次；拒绝、撤回和私人题目不奖励；规则版本切换不重算旧投稿；多阈值发放与账本余额一致；事务故障回滚。
- API 与权限测试：普通用户不能管理奖励规则和公告；用户不能读取他人奖励记录或草稿公告；图片路径只能访问被允许的公告资源。
- 公告测试：草稿、上架、下架状态的首页可见性；安全内容块渲染；非法图片、超限图片及非 HTTP(S) 链接拒绝；搜索与状态筛选。
- 首页测试：登录后默认路由、导航可达性、站内目标和外链；无公告、单公告、多公告和失效详情状态。
- 浏览器检查：桌面和窄屏下公告轮播、详情滚动、卡片换行、首页入口布局及后台公告编辑流程；确认固定/长文本不遮挡相邻内容。

## 范围外

- 不接入联动小铺、飞书 API 或外部内容管理平台。
- 不抓取、复制或镜像 PDF 关联的付费资料；首页只呈现 PDF 提供的名称、链接、优先级与访问提示。
- 不展示旧模拟面试服务地址，不将白皮书中的QQ群二维码作为首页核心入口。
- 不在本次变更中重写每日训练、面试、上机考试或既有认证流程。
