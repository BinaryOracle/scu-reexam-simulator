# 算法带刷题库

前台「算法带刷」提供阶段题单、筛选排序、已完成/未通过进度、账号收藏、每日一题、私人投稿与代码工作区；收藏保存在 SQLite 并按用户隔离，完成状态按当前题目内容版本计算。提交反馈在代码工作区的提交记录面板中展示。后台「带刷题库」管理阶段、顺序、星级、启停、投稿审核与奖励规则。比赛与带刷使用独立提交表和桥接上下文，不共享提交编号空间。

## 来源与内容

已整理《机试历年真题大全 + 全程算法带刷题单！！！》26 页及《历年笔试_上机算法题归类汇总 (模版题为主)》170 页，共 606 个链接注释、119 个题目或模板小节。种子包含 430 道题：347 道保留洛谷原题及公开样例，83 道为明确标注的标准输入输出适配练习。后者保留原站链接、PDF 页码和代码摘录，另提供核对过的 Python 3 参考程序与每题三组公开样例；共 249 组参考程序样例已验证。

八个阶段依次为语法/数组/字符串、数据结构/排序、递归/分治/搜索、二分/贪心/数论、动态规划、图论/树、进阶专题、综合压轴。星级与难度是教学编排建议，不是官方考试命中率或外站难度评级。原 PDF 的历史考试描述不是当前官方考试规则。

`app/assets/coding/catalog.json` 是幂等初始化种子，运行数据保存在 SQLite。`source-inventory.json` 逐项记录来源链接和章节的归属；`guide-extracted.json`、`templates-extracted.json`、`template-sections.json` 保存可追溯摘录；`luogu-cache.json` 缓存公开题面；`local-templates.json` 保存适配题。PDF 原代码可能存在排版错误、缺少上下文或算法错误，页面将其与核对过的参考程序分开展示。来源中的字符串乘法、逆序对另站链接按相关练习标注，不冒充可直接跨平台提交的同一道题；实数负指数快速幂独立于模幂练习。

重建与核对：

```sh
.venv/bin/python scripts/import_coding_sources.py --verify
.venv/bin/python scripts/import_coding_sources.py --extract --pdf-dir ~/Downloads --refresh --verify
```

默认重建使用已保存的来源数据，不联网、不修改数据库。`--verify` 仅执行整理后的受信参考程序，不执行 PDF 原始代码。远端题面失败会明确记入审计清单并令完整性校验失败；初始化不覆盖管理员已经编辑的题目。

## 评测部署

```sh
docker build -t scu-judge:1 judge
```

`config.toml` 的 `[judge]` 统一管理镜像、运行/编译/清理超时、内存、输出和文件大小限制，默认值见 `config.example.toml`。C、C++11、Python 3 代码在无网络、非 root、只读根文件系统的受限容器中运行。缺少 Docker 或新镜像时明确显示不可用，不回退到宿主机执行。公开样例通过不代表通过完整隐藏测试；洛谷题走原浏览器扩展，扩展需更新至 1.1.5。桥接返回测试点统计及编译错误，未取得明细时明确说明无法统计，不伪造用例数。

## 每日题与奖励

以北京时间日期固定当天一题，公开启用题及本人私人启用题可参与；通过当天题的当前内容版本后才能打卡。连续第 N 天且 N 为 7 的倍数时，普通用户获得 N/7 次面试；重复请求不重复入账。首次审核公开的投稿累计奖励默认每五题一次面试，后台修改规则只影响之后的首次通过记录。管理员不领取奖励。题目内容版本变化使旧通过不再计入当前进度，排序、星级调整不清空进度。

洛谷评测状态目前由登录用户的浏览器扩展报告，服务端检查归属、远端编号绑定、题号及终态，但没有独立核验外站结果真实性。此模式适合学习激励，不能作为防作弊成绩或可抵御伪造的奖励结算；详见 [设计说明](coding-practice-plan.md#通过记录内容修订与远端确认限制)。
