# 数据备份与恢复

超级管理员登录后台，进入「系统设置 → 数据备份与恢复」。普通管理员和普通用户均不能下载、预览或恢复备份，避免泄露其他管理员的账号密码及权限信息。

## 备份

默认全选十二个模块。可以全选、清空或分别选择，再点击「下载备份 ZIP」。界面提供各模块的记录数以及媒体文件数量和大小；「刷新统计」保留当前选择。

- 账号与权限：账号资料、邮箱、状态、权限、密码哈希和加密保存的密码。
- 模拟面试：面试记录、回答、PPT 目录和录音索引。
- 面试题库与题目图片：面试题目及训练、算法题共用的 Markdown 图片引用。
- 上机考试：比赛、题目、参赛关系、提交代码和结果。
- 每日训练：题库、训练记录、掌握程度、签到及投稿奖励规则和记录。
- 算法带刷：题库、提交、收藏、评论、签到及奖励记录。
- 课程与直播课：课程主体、章节、课时、学习进度、直播、互动、资料和录播索引。这两个模块会同时勾选或取消。
- 积分与兑换：卡密、套餐、积分流水、转赠、购买和排行榜结算。与账号模块联动，保持钱包余额和流水一致。
- 公告与趋势：公告、阅读状态及 AI 趋势内容。
- 系统设置：后台业务配置、首页设置、初始化标记和加密的模型服务凭据。
- 媒体文件：当前配置目录中的录音、PPT、视频、资料、封面、公告图片及题目图片。

备份包含 `manifest.json`、按模块分目录保存的表 JSON、文件校验值和可选媒体文件；账号或设置模块还包含配套密码加密密钥。媒体文件使用逻辑目录标识，恢复到另一台机器时按目标机器配置映射路径，嵌套目录不会重复打包。不存在的媒体目录会列入备份清单和恢复预览的提醒；文件无法读取时导出失败，不会生成表面成功的残缺下载。

**备份 ZIP 没有额外加密，持有备份及其中的密钥即可读取账号密码和加密凭据。** 请保存到受保护的私有位置，需要异机保存时使用加密存储或加密传输，不要上传至公开仓库或公开网盘。

登录会话、邮箱验证码和限流记录、临时播放令牌、在线状态及语音合成缓存不属于持久备份内容。运行配置 `config.toml`、环境变量、LiveKit/Egress/Redis 配置和凭据、TLS 文件及外部服务数据仍需按 [部署文档](deployment.md#备份与恢复) 单独保管。

## 加载与恢复

1. 先结束正在进行的面试、直播和录制，暂停其他操作，在单进程应用的维护时段进行恢复。
2. 选择新版 ZIP 文件，点击「上传并校验」。这一步只校验备份，不修改业务数据或媒体。
3. 系统检查 ZIP 路径、数量和体积限制、文件 SHA-256、数据库版本、表结构、字段、密码及模型密钥的解密能力，并在临时数据库执行替换和完整性检查。
4. 核对备份时间、模块范围、记录数、媒体数量及提醒。当前只恢复这份备份内的全部模块；需要局部恢复时，应先导出相应模块的备份。
5. 点击「恢复这份备份」，在站内确认框确认替换。系统先保存当前数据库、密码密钥及被覆盖文件的安全副本，再事务性替换数据，安装备份媒体文件。
6. 成功后所有用户需重新登录。账号模块保留备份时的用户名和登录密码；后台查看密码继续可用。跨机器恢复会将备份密文用目标系统现有密钥重新加密，目标密钥不被替换，因此未恢复模块的原有密文仍可读取。

恢复使用替换语义：备份内模块的现有记录会被替换，备份外模块保留。局部恢复会检查关联账号的 ID、用户名及邮箱是否一致，避免记录关联到其他用户；数据关联缺失时会拒绝操作，需把关联模块一同备份并恢复。其他题目和课程的引用仍依赖原有 ID，跨环境迁移应全量恢复，不应把不同来源的局部备份拼接混用。完整迁移建议全选。媒体文件按备份覆盖同路径文件，保留未被覆盖的其他文件，避免破坏未恢复模块的数据。未包含媒体时只恢复数据索引，相关文件必须已存在于目标存储。

数据库 schema 版本和表结构必须与当前程序匹配，不会尝试把高版本数据库降级。旧版 `scu-reexam-backup-v1` 是脱敏导出，缺少密码与路径信息，不能用于本功能恢复；请使用新版 `scu-reexam-backup-v2` 重新备份。

## 失败与安全副本

正常校验失败不改变当前数据。恢复执行过程中发生错误时，数据库事务回滚，已经替换的媒体也从安全副本回退。应用恢复期间拒绝新请求；另有请求处理中、面试进行中、直播或录制进行中时拒绝开始恢复。恢复成功会清理全部旧会话和播放令牌，不会恢复旧登录状态。

安全副本位于 `[backups].directory` 下的 `before-restore-*` 私有目录，含 `database.sqlite3`、`password-view.key`、`rollback.json` 以及被覆盖文件的旧副本 `media/`。SQLite 在线备份 API 同时覆盖 WAL 中的已提交数据；保存的数据库可单独打开。安全副本含敏感数据，不应公开挂载。系统不会自动清理，运维人员应根据保留策略和磁盘容量管理。

进程被强制终止或磁盘损坏可能阻止自动回退。如果接口明确报告部分文件无法回退，停止应用后人工处理：恢复该目录中的数据库和配套密钥到运行配置指定位置；确认没有残留运行进程后清理旧数据库的 `-wal`、`-shm`、`-journal` 侧文件；根据 `rollback.json` 把存在的 `previous` 文件（相对安全副本目录）复制回 `target`。`previous` 为 null 表示恢复前不存在该文件，可删除此次新建的目标文件；旧副本尚不存在的条目表示尚未执行覆盖，不应据此删除原文件。随后启动应用，抽查登录、密码查看、PPT、录音和课程资料。安全副本用于故障运维，不作为 ZIP 上传入口。

## 配置与部署

配置集中在 `config.toml` 的 `[backups]`，省略时使用以下默认值：

```toml
[backups]
# 默认是数据库同目录的 backups/；不要放到公开静态目录。
# directory = "/srv/scu/data/backups"
max_upload_mb = 4096
max_expanded_mb = 16384
max_entries = 100000
max_rows_per_table = 1000000
```

上传大小在请求接收和 ZIP 校验阶段检查；展开体积、文件数量和单表记录数超过限制时拒绝恢复。备份 ZIP 通过服务端临时文件下载，媒体按块打包；数据库 JSON 和校验数据库仍需要内存空间。确保临时目录、媒体存储和安全副本目录有足够空间，反向代理的上传限制及超时也应匹配配置。

在线恢复仅支持本项目当前的单进程部署，不要在多个 Uvicorn worker 或多个应用实例共同写同一数据库时执行；内存中的维护拦截不能跨进程同步。恢复期间还应暂停外部备份、文件清理任务和 Egress 写入。部署配置和外部服务恢复仍按部署文档的停机流程执行。
