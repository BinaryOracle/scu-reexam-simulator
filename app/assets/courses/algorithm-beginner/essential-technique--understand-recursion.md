# 一个视角 + 两种思维模式搞定递归

## 学习目标

把递归调用视为树，明确函数返回值、终止条件和状态恢复。

## 不追踪所有调用，先规定一个调用的含义

例如 `sum(n)` 的含义是返回 1 到 n 的和。只要 `sum(n-1)` 能完成同类任务，当前调用就返回 `n + sum(n-1)`；终止条件为 n=0。这个推理依赖参数逐步接近终止条件，不能只有递归调用而没有进展。

```cpp
long long sumTo(int n) {
    if (n <= 0) return 0;
    return n + sumTo(n - 1);
}
```

示例用于理解调用含义，不推荐对极大 n 这样求和：其时间和栈空间都是 O(n)，还存在溢出风险。递归形式是否优雅与其是否适合输入规模是两回事。

## 遍历与分解的差异

分解式递归通过返回值组合答案；遍历式递归在访问过程中维护路径、计数等状态。生成排列常采用后者：选择一个元素、递归处理剩余选项、返回后撤销该元素。路径若被多个分支共用，必须在离开分支前恢复。

斐波那契递归的不同分支会计算同一个参数，形成重复子问题，可加入备忘录；排列生成中不同路径通常代表不同输出，不能只根据深度缓存一个结果。先画调用树，再判断重复状态究竟是否等价，有助于避免误用记忆化。

## 动手练习

1. 画出 sumTo(3) 的调用和返回顺序。
2. 把示例改成迭代，比较时间、空间和适用规模。
3. 画出三个不同元素的排列树，指出一次选择和撤销的位置。
