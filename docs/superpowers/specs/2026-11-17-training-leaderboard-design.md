# 每日训练与算法带刷排行榜设计

## 目标

为每日训练和算法带刷提供统一的累计排行榜，展示普通用户的用户名以及三项指标：打卡天数、每日抽题训练数量、上机训练通过题目数量。管理员账号不进入榜单，也不向普通用户暴露管理员用户名或管理数据。

## 统计口径

- 打卡天数：合并每日训练打卡表与算法带刷打卡表的记录数；相同用户同一天在两个模块都打卡时，按两次业务打卡计数。接口同时返回两个来源的分项值，页面使用合计值。
- 抽题训练数量：统计 `training_daily_questions` 中的记录数；该表的唯一键保证同一用户同一天同一道题只计一次。
- 上机通过题目数量：统计 `coding_submissions` 中状态为 `Accepted` 的不同 `question_id`，避免重复提交同一道题重复计数。
- 用户筛选：所有榜单查询都连接 `users` 并使用 `is_admin=0`；返回 `username`，不返回密码、管理员额度或其他账号私密字段。
- 排序：指标降序，指标相同时按用户名升序，再按用户 id 升序，保证结果稳定。
- 范围：V1 使用累计总榜，不引入月份切换和时区边界。

## 后端结构

新增 `app/services/leaderboard.py`，只负责读取和组合排行榜数据，不修改训练或评测业务表。新增 `GET /api/leaderboard`，返回三张榜单以及当前用户在各榜单中的排名；响应中的每一行包含 `rank`、`username`、`value`、必要的分项值和 `is_current_user`。

服务层使用参数化 SQL，并限制默认返回条数；当当前用户是管理员时不返回其排名。无数据时返回空列表和明确的零值。

## 前端结构

每日训练和算法带刷导航各增加“排行榜”入口，共用 `app/static/leaderboard.js` 与 `app/static/leaderboard.css` 的渲染和视觉规则。页面顶部使用三项指标切换，桌面端显示前三名突出卡片和后续列表，移动端使用横向切换。当前用户行使用轻量强调色；列表只展示用户名和排名指标，避免展示管理员额度、内部 id 或其他敏感字段。

榜单加载失败时保留当前模块页面，并显示可重试的局部错误提示；空榜显示引导文案，不弹出浏览器原生弹窗。

## 测试

后端覆盖普通用户筛选、管理员排除、Accepted 去重、并列稳定排序、当前用户排名和空数据。路由覆盖未登录与模块权限校验。前端覆盖三项榜单切换、当前用户高亮、空状态和接口错误重试。
