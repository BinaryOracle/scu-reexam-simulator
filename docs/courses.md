# 课程、直播与自动回放

## 使用

管理员登录 `/admin`，点击「课程管理」：

1. 新建课程，填写名称、简介。默认保存为草稿；勾选「发布课程」后，具有观看权限的学员可以看到课程。
2. 添加课节，填写标题、简介和排序值。课节按排序值从小到大排列，同值按创建顺序排列。
3. 每节固定包含「资料 / 录播 / 直播」。资料支持多文件，视频支持 MP4 / WebM；文件逐个上传。
4. 设置北京时间的直播开始和结束时间；不直播的课节可将两项都留空。
5. 到课节的「直播」页选择「摄像头 + 麦克风」或「屏幕共享 + 麦克风」。提前授权后显示预览，到达排期自动开播，结束时间自动停止并生成回放。也可手动「结束直播并保存」。

学员登录前台后点击「课程」，选择课程与课节。资料可下载，录播可站内播放。直播页自动刷新状态，老师开播、首批视频就绪后出现「观看直播」。结束后进入「录播」查看自动回放。同一课节可保留多份手动录播和多场直播回放。

每门课可以单独设置「观看权限」：选择「仅指定学员」，按用户名或邮箱搜索并勾选学员，保存后生效；取消勾选并保存即可撤销权限。新课程默认仅指定学员、名单为空；旧课程保持原来的开放范围。也可按需选择「所有已注册学员」。草稿对学员隐藏，已停用的账号无法访问。权限覆盖课节、资料、录播、直播及回放，直接打开媒体链接也会检查权限；已经下载的文件不受撤销影响。

普通用户不能访问课程管理 API。删除课程或课节会要求确认，并清理相关数据库记录与私有文件；直播中不能删除所属课程、课节、更改排期或下架课程。

## 定时开播的前提

授课人必须先确认摄像头或屏幕共享授权。排期不会在无人授权、电脑关机或页面关闭时自行采集设备。要定时开播，必须事先进入直播页授权，保持页面打开、电脑唤醒和网络连接。

使用支持 WebM MediaRecorder 的桌面 Chrome / Edge 授课；屏幕共享模式录制共享画面和麦克风，不混录共享窗口的系统声音。生产环境使用 HTTPS，开发可使用 `http://localhost` 或 `http://127.0.0.1`。浏览器弹出的设备选择和共享范围需要授课人亲自确认。

学员端优先使用原生 HLS，否则按需加载本地 HLS.js，不依赖外部 CDN。直播有数秒延迟，适合授课观看，目前没有双向连麦、聊天或大规模 CDN 分发。

刷新、离开页面、设备停止或断网会停止本场直播。后台尽力保留已完整收到的分片；空流或未形成完整分片的流不会被标记为可播放回放。进程意外退出后，超过 30 秒心跳租约的直播会在下一次课程读取时恢复归档。重新授权开播会创建新回放。重要课程仍建议授课端另存本地备份。

## 安装与部署

安装依赖并重新启动现有服务：

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

服务端使用 FFmpeg 转成 H.264/AAC HLS。优先使用配置或 PATH 中的 FFmpeg；默认未找到时使用 `imageio-ffmpeg` 依赖自带的二进制。不支持随包二进制的平台，需安装支持 libx264、AAC、WebM 输入和 HLS 输出的 FFmpeg，并在配置中填写绝对路径。编码器不可用时开播会明确提示；课程、资料和已上传录播仍可使用。

`config.example.toml` 中的 `[courses]` 提供以下选项：

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| directory | 数据库旁的 courses/ | 私有课程文件、直播分片和回放 |
| max_material_mb | 50 | 单个资料上传上限 |
| max_video_mb | 1024 | 单个录播上传上限 |
| max_live_minutes | 180 | 单场排期最大分钟数 |
| max_concurrent_live | 1 | 全站同时直播场数上限 |
| ffmpeg | ffmpeg | 编码器命令或绝对路径 |

大文件逐块写盘，视频支持 Range 请求。直播分片直接作为回放保存，结束时封存播放列表，不必等待整场再次转码。私有目录不会挂载为静态文件。

生产反向代理必须转发 `/api/course-media/` 的 WebSocket Upgrade 和原始 Host、支持 HTTPS/WSS，并将 HTTP 上传体上限设为不小于录播上限。在 TLS 由代理终止时，转发 `X-Forwarded-Proto: https`，让 Uvicorn 信任该代理的 IP。代理读取超时应覆盖直播时段，不能缓冲 WebSocket。HTTP 媒体通过 HttpOnly、SameSite=Strict、限于媒体路径的会话 Cookie 认证；退出或停用账号后媒体凭证失效。推流校验同源 Origin，并定期复查管理员权限。

同一台服务器运行多个 worker 时，应使用同一个本地数据库和私有文件目录。跨主机部署或较大直播并发需另外规划数据库、转码、存储、出站带宽与分发；默认一路、720p 编码未经过线上压力测试。

启动将数据库迁移到版本 27，新增课程观看范围和学员授权表，保留现有课程与文件。升级前备份数据库；日常备份与迁移时复制整个课程目录。不要将课程目录配置到 `app/static` 等公开位置。

## 验证

```powershell
.venv\Scripts\python.exe -X utf8 -m pytest tests/test_courses.py -q
```

覆盖草稿隔离、管理员权限、指定学员与撤销授权、媒体直链校验、旧课程权限迁移、排序、排期校验、视频 Range、大小限制、关联清理、直播锁、进程中断恢复，以及真实 WebM 经 FFmpeg 转为直播、归档回放的完整流程。

`tests/course_browser.py` 是额外的 Playwright 验收脚本，开发环境需安装 `playwright` 和本机 Chrome。仅针对独立测试数据库运行：脚本使用该数据库的默认 root/root 创建验收课程和普通学员，使用虚拟摄像头测试真实推流、定时开播和结束，并检查学员直播/回放、资料下载、手动录播与手机布局。截图位于已忽略的 `output/course-qa/`，不要对正式数据库运行此脚本。

参考：[FFmpeg HLS muxer](https://ffmpeg.org/ffmpeg-formats.html#hls)、[HLS.js](https://github.com/video-dev/hls.js)、[MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder)、[屏幕共享授权](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia)。
