# 一行代码就能解决的算法题

## 学习目标

先证明特殊条件下的数学结论，再把结论压缩成简单实现。

## 简短代码需要完整前提

某些题目在证明后可以一行求解，但不能从代码长度倒推问题难度。Nim 游戏若只有一堆石子、每次取 1 到 3 颗、取走最后一颗获胜，则先手在 n 是 4 的倍数时无法保证取胜。

```cpp
bool canWinNim(int n) { // 前提：n > 0
    return n % 4 != 0;
}
```

理由是先手无法从 4 的倍数一步到达另一个 4 的倍数；而从其他数可以拿到 4 的倍数，随后每轮让双方合计取 4 颗。若一次允许取的数量或获胜条件变化，就要重新推导。

## 从不变量找规律

经典偶数堆石头游戏在正数、总和为奇数等特定条件下，先手可以选择控制原下标奇偶性中的一组，得到较大的一组总和。这个结论不适用于任意轮流取数游戏，前提缺失时应回到动态规划。

开关灯问题中，第 i 盏灯被每个约数操作一次，最终亮灯取决于约数个数的奇偶。约数通常成对，只有完全平方数拥有一个不配对的平方根，所以前 n 盏灯最终亮着的数量为 floor(sqrt(n))。实现大整数平方根时要处理浮点误差和乘法溢出。

这些例子训练的是从操作中寻找保持不变或成对出现的结构，而不是背诵三行答案。

## 动手练习

1. 手算 n=1 到 12 的 Nim 胜负，验证 4 的周期。
2. 为 1 到 16 逐个列约数，核对灯的最终状态。
3. 改变 Nim 的取数范围或“拿最后一个输”的规则，说明原结论是否仍成立。
