# 一致性哈希算法的原理及实现

## 学习目标

理解哈希环、顺时针归属与虚拟节点，分析扩缩容时的数据迁移范围。

## 为什么不是简单对服务器数取模

把键哈希后对服务器数量取模，服务器数量变化时，大量键的结果可能改变。一致性哈希把服务器与键映射到同一固定哈希空间；键沿环顺时针归属于第一个服务器位置，超过最大位置时回绕到最小位置。

```text
locate(key):
    如果哈希环为空，报告没有可用节点
    point = stableHash(key)
    it = ring.lower_bound(point)
    如果 it 到达末尾，令 it = ring.begin()
    返回 it 对应的物理服务器
```

新增一个节点时，主要接管它与前驱之间的区间，其他区间归属通常不变；删除节点时，其区间交给后继。这减少迁移范围，但不意味着完全不用迁移，也不意味着天然解决副本、故障恢复与并发写入。

## 虚拟节点与一致性

一个物理节点对应多个散布在环上的虚拟位置，可以改善节点少时的负载不均。节点权重可通过虚拟位置数量近似反映。需要固定且跨进程一致的哈希算法和节点命名方式，不能使用每次启动会改变结果的随机散列规则。

若环中有 m 个虚拟位置，使用有序结构查找通常 O(log m)。还应考虑哈希碰撞、节点变更期间旧数据读取和热键分布，均匀的键归属并不自动带来均匀的请求负载。
