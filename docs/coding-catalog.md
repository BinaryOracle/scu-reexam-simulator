# 算法带刷题库

前台「算法带刷」提供阶段题单、筛选排序、已完成/未通过进度、账号收藏、每日一题、私人投稿与代码工作区；收藏保存在 SQLite 并按用户隔离，完成状态按当前题目内容版本计算。提交反馈在代码工作区的提交记录面板中展示。后台「带刷题库」管理阶段、顺序、星级、启停、投稿审核与奖励规则。比赛与带刷使用独立提交表和桥接上下文，不共享提交编号空间。

## 外站题目和桥接

算法带刷和比赛共用平台适配注册表，逐题保存来源平台、原题编号、来源链接和官方代码模板。比赛可混合洛谷与 LeetCode 中国区题目；旧题迁移时来源默认为洛谷。管理员可从任一平台搜索并导入比赛题目，普通用户可将外站题导入为自己的私人题目。题面、样例和提交记录均按题目来源显示并调用对应桥接器。

LeetCode 搜索和导入通过 `leetcode.cn` 公开题库接口完成，原题链接固定为 `https://leetcode.cn/problems/{slug}/`；`leetcode.com` 链接不会被接受。浏览器插件只查询 `leetcode.cn` 标签页，并在用户已登录的标签页提交代码和读取判定。LeetCode 题目编号大小写保持原样。插件使用平台页面现有的提交和状态查询接口，平台页面改版可能要求更新插件；外站账号、密码和 Cookie 不会传给知序服务器。浏览器回传的判定没有由服务端向平台二次认证，不适合用作防作弊成绩凭证。

## 来源与内容

已整理《机试历年真题大全 + 全程算法带刷题单！！！》26 页及《历年笔试_上机算法题归类汇总 (模版题为主)》170 页，共 606 个链接注释、119 个题目或模板小节。种子包含 430 道题：347 道保留洛谷原题及公开样例，83 道为明确标注的标准输入输出适配练习。后者保留原站链接、PDF 页码和代码摘录，另提供核对过的 Python 3 参考程序与每题三组公开样例；共 249 组参考程序样例已验证。

八个阶段依次为语法/数组/字符串、数据结构/排序、递归/分治/搜索、二分/贪心/数论、动态规划、图论/树、进阶专题、综合压轴。星级与难度是教学编排建议，不是官方考试命中率或外站难度评级。原 PDF 的历史考试描述不是当前官方考试规则。

`app/assets/coding/catalog.json` 是幂等初始化种子，运行数据保存在 SQLite。`source-inventory.json` 逐项记录来源链接和章节的归属；`guide-extracted.json`、`templates-extracted.json`、`template-sections.json` 保存可追溯摘录；`luogu-cache.json` 缓存公开题面；`local-templates.json` 保存适配题。PDF 原代码可能存在排版错误、缺少上下文或算法错误，页面将其与核对过的参考程序分开展示。来源中的字符串乘法、逆序对另站链接按相关练习标注，不冒充可直接跨平台提交的同一道题；实数负指数快速幂独立于模幂练习。

旧数据库启动升级时，先为题目和提交补齐 `remote_platform` 等字段，再把远端提交唯一索引迁移到「平台 + 提交编号」。已有记录的平台默认为 `luogu`，保留题目、源码、成绩和提交编号；重复启动不重复增加字段或重建已升级的索引。若旧代码启动时报 `no such column: remote_platform`，更新代码后重新启动即可完成迁移，无需删除数据库或手动修改数据库版本；升级前应备份数据库。

重建与核对：

```sh
.venv/bin/python scripts/import_coding_sources.py --verify
.venv/bin/python scripts/import_coding_sources.py --extract --pdf-dir ~/Downloads --refresh --verify
```

默认重建使用已保存的来源数据，不联网、不修改数据库。`--verify` 仅执行整理后的受信参考程序，不执行 PDF 原始代码。远端题面失败会明确记入审计清单并令完整性校验失败；初始化不覆盖管理员已经编辑的题目。

## 评测部署

```sh
sh scripts/prepare_judge.sh
```

首次部署需要启动 Docker Desktop；准备脚本会构建配置默认使用的 `scu-judge:1` 镜像，镜像内含 C、C++11 和 Python 3 运行环境。`config.toml` 的 `[judge]` 统一管理镜像、运行/编译/清理超时、内存、输出和文件大小限制，默认值见 `config.example.toml`。这些语言的代码在无网络、非 root、只读根文件系统的受限容器中运行。Docker Engine 未运行或镜像尚未准备时，页面会禁用运行按钮；服务不会回退到宿主机执行用户代码。公开样例通过不代表通过完整隐藏测试；洛谷与 LeetCode 中国区题使用多平台浏览器扩展，扩展需更新至 1.3.0。桥接返回平台可提供的测试点统计及编译错误，未取得明细时明确说明无法统计，不伪造用例数。

## 每日题与奖励

以北京时间日期固定当天一题，公开启用题及本人私人启用题可参与；通过当天题的当前内容版本后才能打卡。连续第 N 天且 N 为 7 的倍数时，普通用户获得 N/7 积分；重复请求不重复入账。首次审核公开的投稿累计奖励默认每五题获得 1 积分，后台修改规则只影响之后的首次通过记录。管理员不领取奖励。题目内容版本变化使旧通过不再计入当前进度，排序、星级调整不清空进度。四个独立周榜的指标、结算时刻与 3/2/1 积分奖励见[积分与卡密说明](credits-and-vouchers.md#每周排行榜)。

洛谷评测状态目前由登录用户的浏览器扩展报告，服务端检查归属、远端编号绑定、题号及终态，但没有独立核验外站结果真实性。此模式适合学习激励，不能作为防作弊成绩或可抵御伪造的奖励结算；详见 [设计说明](coding-practice-plan.md#通过记录内容修订与远端确认限制)。

## Markdown 题目编辑与图片

新建和编辑题目使用统一 Markdown 编辑器：可切换编辑、双栏和预览，支持标题、列表、表格、代码、公式、导入 UTF-8 `.md` 文件，并通过“上传图片”或粘贴剪贴板图片插入正文。每日训练的参考答案也使用同一编辑器。上传和预览失败时保留输入，上传期间禁止保存，成功上传不代表题目已经保存。

题目图片由服务端验证并重新编码，只接受 PNG、JPEG、WebP，默认最大 5 MiB、2400 万像素。配置集中在 `[question_media]`：`directory` 为私有图片目录，`image_max_mb` 可设为 1–20。不要把图片目录映射到静态网站；图片接口验证当前账号及题目权限，私人草稿不向其他用户或普通管理员开放，送审后审核管理员可查看，公开后有对应训练权限的用户可查看，撤回或删除后立即收回其他用户访问。图片与数据库一起备份；未保存到题目的上传仅上传者可读。

数据库通过 v38 初始化新增图片及题目引用表，保留已有题目与学习记录；升级前备份数据库和私有文件目录。

## 题目选择与列表编号

新增与编辑题目统一在“评测方式”选择公开样例、洛谷评测或 LeetCode 中国区评测。外部评测直接在“题目名称”输入名称、编号或原题链接，选择联想结果后自动载入题面、样例及平台代码模板，无需另填平台题号。切换平台或修改名称后需重新选择题目；搜索或导入失败会保留正文并提示重试。

题单左侧数字为当前筛选、排序后的连续序号，翻页后接续编号；私人题与公开题共同编号，不使用可重复的后台“列表顺序”作为题号。已完成题目仍展示完成标记。

## 两种本地测试格式

算法带刷、课程内写题和比赛样例运行按题目来源选择适配器，不改变正式提交的平台。洛谷与公开样例题仍运行完整程序，输入为标准输入文本，输出按空白分隔比较。LeetCode 中国区题运行平台的函数模板，由隔离评测器补齐调用程序；不需要另写 `main`。题目导入同时保存 `metaData` 函数签名，旧题首次运行时从中国区补取并缓存，失败会提示重试，不会修改题面或生成提交成绩。

新增/编辑题目的公开样例与写题页的自定义用例均显示对应格式说明。力扣输入可使用每行一个 JSON 参数值、参数名赋值或以参数名为键的 JSON 对象；数组整体作为一个参数，字符串使用双引号，布尔值使用 `true/false`。例如两数之和可填写：

```text
nums = [2,7,11,15]
target = 9
```

对应期望输出为 `[0,1]`。也可以只写 `[2,7,11,15]` 和 `9` 两行。返回值按 JSON 结构比较，保留字符串中的空格，数值误差容限为 1e-6；无返回值函数比较修改后的第一个参数。数组顺序敏感，不替代力扣的特殊判题或隐藏测试。

本地函数测试支持 C++11、Python 3 的标量、二维以内数组、链表和二叉树，链表/树使用数组表示，树为空的位置填写 `null`；C 支持标量及一维数值/字符数组，采用力扣的指针、长度和 `returnSize` 约定。设计类、多级复杂节点等尚未支持的函数签名会明确说明并引导使用平台提交；C 的复杂指针题可改选 C++11/Python 3。全部用户代码均在原有无网络 Docker 沙箱中执行。
