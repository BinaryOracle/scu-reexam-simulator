# 模拟面试次数与卡密

普通用户默认拥有 1 次免费面试。后台「卡密与次数」可修改后续新用户的默认值，创建账号时也可指定初始次数；账号列表可单独调整剩余次数。管理员统一使用数值 999999，开始面试不扣减，管理员无需兑换卡密。该内部数值不返回前台登录、账号与个人主页 API，前台只显示“已开通”；后台账号管理 API 可读取数值。管理员尝试兑换时返回未消耗卡密的提示。所有启用账号均可访问两个系统，模拟面试由余额控制，兑换成功增加次数，无需额外授权。

准备、选择 PPT、麦克风检测、浏览和复盘不消耗次数。PPT 转换成功并正式创建、开始面试时，在同一个 SQLite 即时事务中扣除一次；余额不足会回滚场次并清理转换文件。旧准备场次通过开始接口首次启动时扣一次，重复开始不重复扣。已有已开始的历史记录迁移后继续使用，不追扣次数。主动结束、超时和删除面试记录不返还次数，避免删除记录绕过额度限制；页面刷新后的恢复录音也不重复扣次。

`[credits].default_credits` 是数据库首次初始化的默认值，默认 1；后台修改保存到 `app_settings`，后续以数据库中的设置为准，不覆盖已有用户余额。`max_voucher_batch` 默认 500，限制一次批量生成的数量。`[credits.packages]` 仅在首次创建套餐表时导入初始套餐，支持合法标识的任意套餐；示例包含原两档，已有卡密升级时保留发行数据。运行期间 `voucher_packages` 为套餐的权威数据来源，后台新增套餐通过 `POST /api/admin/voucher-packages` 保存金额（整数分）和次数；同金额、同次数不能重复创建。前端将元按小数位精确转换为分，金额不使用浮点乘法取整。新增后即出现在生成、筛选和导出列表；修改配置不会覆盖数据库套餐，发行卡密仍保存次数、标价快照。

卡密形如 `XXXX-XXXX-XXXX-XXXX-XXXX-XXXX`，由安全随机源从不含易混淆字符的 32 个字符中独立取 24 位，随机空间为 120 位，不包含时间戳或递增 ID。数据库为完整卡密设置唯一约束；碰撞时重试，连续失败则回滚整批，不产生重复卡密。卡密是持有者可兑换的凭证，应只向管理员及购买者提供。

后台按数据库套餐分别管理卡密，可按未兑换／已兑换、生成批次、卡密或兑换用户名查询，分页显示。生成后自动筛选本批次。导出当前套餐、兑换状态和批次范围内的卡密为 TXT，一行一卡密，可由管理员手动上传联动小铺；本站不调用商城接口、不收款，不自动同步订单、退款或发卡。导出不会改变状态，未兑换不等于尚未售出；请按新生成批次上架，避免重复上传同一卡密。关键词搜索仅用于查看，导出按钮明确按套餐、状态与批次导出。

用户点击头像进入个人主页，查看剩余次数、兑换记录及累计兑换套餐标价，并可退出登录。主页始终提供“兑换码”输入框与兑换按钮，不显示套餐推介卡片；兑换失败在输入框下方说明，内容保留供修改。退出通过 `POST /api/logout` 撤销当前服务器会话。金额是已兑换卡密发行时的标价之和，不是商城实际付款凭证，无法反映外部折扣、退款或未兑换卡密。兑换接受小写、连字符或空白分组，校验后统一为标准格式。即时事务中检查卡密未使用、绑定兑换用户、增加余额并记录账本；并发兑换同一卡密仅一笔成功。普通用户只能看到自己的记录及卡密尾号，管理员才能查看完整卡密列表、生成及导出。

SQLite v8 为后台密码查看增加密文列，v9 增加用户余额、场次扣减标记、`app_settings`、`vouchers` 与 `credit_ledger`。升级时已有普通用户获得当前配置的默认体验次数，管理员调整为 999999；重复启动不会重置余额或重新发放体验次数。删除面试不会删除兑换记录和次数账本。v10 新增 `users.is_superadmin` 与单一超级管理员索引、动态套餐表，并迁移卡密为套餐外键。升级时优先将已有 root 管理员标记为超级管理员，无 root 时选择最早管理员；只绑定一次，不随用户名变更或后续启动转移。删除用户会清理其私有数据及账本，卡密保留兑换时间与用户名快照，兑换用户 ID 可置空；使用状态及防重复兑换依据 `redeemed_at`，避免删号后已用卡密变成未用。

主要实现：`app/services/credits.py` 管理额度事务，`app/routes/credits.py` 提供个人主页、兑换及后台接口，`app/static/credits.js` 和 `credits.css` 管理对应页面。后端测试见 `tests/test_credits.py`，覆盖并发兑换、并发开始面试、迁移、金额统计、越权访问、分套餐与分批导出。

## 管理员查看密码

登录继续使用 scrypt 哈希验证。为满足明确的管理员查看要求，创建／重置密码时另存 Fernet 认证加密副本，有该账号管理权限的管理员显式点击后通过专用 POST 接口解密返回，响应禁止缓存；用户列表和普通用户接口均不返回密码或密文。密码显示 15 秒后自动隐藏，也可立即点击隐藏，离开账号页或切换浏览器标签时隐藏。

普通管理员不能查看其他管理员的密码。旧账号没有加密副本时，列表明确显示“需先重置密码”，可打开密码重置对话框。旧账号的哈希不能反推原文；成功登录一次或管理员重置后建立加密副本，迁移不修改旧密码。`[security].password_key_file` 指定密钥位置，省略时使用数据库同目录的 `password-view.key`，首次创建权限为 0600。数据库和密钥必须配套备份；已有密文而密钥丢失时拒绝重新生成，错误密钥或损坏密文会明确报错，不返回假密码。

可恢复密码意味着持有数据库和解密密钥的人可以还原密码，其保护强度弱于只保存哈希的方式。密钥文件不应放进代码仓库、静态目录或卡密导出文件；本地默认 `data/` 已由 Git 忽略。

本次权限、删号、动态套餐、v9 升级与退出会话测试见 `tests/test_admin_roles_v2.py`；浏览器验证记录与截图位于 `output/playwright/admin-v3-*`，破坏性检查使用隔离数据库。

## 店铺购买入口

`credits.shop_url` 配置个人主页卡密兑换区的店铺链接，默认使用 `https://wzyp.cn/shop/E1GQFV0P`，留空可隐藏入口。仅允许 HTTP/HTTPS 链接，不能内嵌用户名和密码；该字段作为公开信息返回，不包含任何支付回调或订单对接。套餐列表仍由后台数据库维护，不在前台写死金额和次数。
