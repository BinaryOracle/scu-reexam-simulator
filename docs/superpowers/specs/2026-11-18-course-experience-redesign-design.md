# 课程系统体验重构设计

## 产品目标

把课程入口、课程发现、内容管理与课时学习组织成一条容易理解的流程。学员应能先判断公开课程是否适合自己，再加入并继续学习；管理员应能从草稿逐步完善课程，而不必在首次创建时处理名单、主持人和发布状态等管理细节。

课程继续支持直播、录播、文档及混合课时。直播课堂的设备、互动、主持人权限、录制和回放由现有直播模块负责；课程系统负责课程目录、课时组织、加入权限及学习进度。

## 信息架构

课程导航进入单一课程中心。学员看到“我的课程”和“课程广场”两个工作区；管理员额外看到“课程管理”。不再并列显示旧直播课程列表与新课程学习列表。直播课次仍属于课程目录，不作为第二套课程入口。

课程首页以继续学习为首要内容，展示最近学习课程、明确的进度和继续学习操作。课程广场提供搜索、课程类型/内容方式线索及课程卡片。课程卡片突出课程名称、简介、主讲人、课时数量、直播/录播/资料构成和开放状态，避免无语义的编号封面。搜索无结果、空广场、加载失败分别给出对应说明和下一步操作。

## 课程预览与加入

已发布的公开课程允许任何已登录用户打开只读预览。预览包含课程简介、主讲人、章节和课时标题、内容类型、直播时间及课程总量；不返回名单、学习进度、私有媒体地址或主持人管理字段。未加入用户不能获取课时内容、附件下载地址、视频播放票据或直播入会凭证。预览页提供明确的加入操作，成功后转为课程学习视图；已加入用户显示继续学习操作。

名单课程仅显示给已分配成员和有管理权限的管理员，不进入公开广场。草稿和归档课程不向普通用户公开。取消发布或撤销名单授权后，原有私有内容访问必须继续由服务端拒绝。

## 学习体验

课程学习页固定为两列工作区：左侧为可折叠章节/课时目录，主体为当前课时内容。当前目录项、内容类型、完成状态和课程总体进度有清晰且一致的视觉层级。课时内按管理员编排顺序呈现直播、录播、资料，可组合多种内容。

视频续播位置自动保存，播放结束可标记完成；资料预览与下载使用稳定且可理解的操作；直播课次展示开课时间和进入课堂状态，并跳转现有沉浸式课堂。上一课/下一课在固定位置显示，课程目录切换不重置其他课时进度。窄屏下目录收为可打开的课时选择面板，内容区保持优先。

## 课程管理体验

管理员的“课程管理”使用独立列表，支持按草稿、已发布、已归档筛选，并显示访问方式、课时数量和最近编辑状态。课程编辑分为三个连续步骤：

1. 基本信息：名称、简介、封面（可选）、课程访问方式。
2. 课程内容：章节与课时；每个课时可加入直播、录播或文档，支持排序和预览。
3. 学员与发布：名单课程的学员分配、直播主持人、发布状态及发布前检查。

草稿可在任意步骤保存并稍后继续。发布检查至少要求课程名称有效、至少有一个章节、至少有一个课时，且每个课时包含可访问的课程内容或已安排的直播。检查结果直接定位到待完善项。创建课程时默认保存为草稿，不要求管理员当场选择主持人和学员。仅在课程内确实包含直播课次时，主持人设置才是必填项。

课程详情的管理员操作集中在“编辑课程”和明确的内容编辑态；章节、课时和资源的高频操作分组呈现。删除仍使用二次确认，并解释直播记录或私有文件的影响。

## 服务端和数据规则

- 增加公开课程预览读取路径，响应只包含可公开展示的字段和课程目录概要。
- 保持现有成员授权作为学习内容、附件、视频票据和直播课堂的唯一访问依据。
- 发布校验在服务端执行，不能依赖前端按钮禁用。
- 保留 `live_courses`、`live_members`、`live_lessons`、录制记录和已有关联 ID；不重建或删除现有直播房间。
- 课程广场、我的课程和课程管理统一使用课程 API；旧的直播安排与课堂操作 API 继续服务直播领域，不再生成另一套课程首页。
- 当前课时的自动进度保存应节流，并在离开页面前完成最后一次持久化；网络失败时清楚提示并允许重试。

## 视觉与交互方向

采用面向长期学习的安静工作台风格：中性浅背景、清晰深色正文、一个品牌强调色和一个进度状态色。信息通过标题、留白、分隔线和内容类型图标组织，减少大面积装饰色块、嵌套卡片、重复标题及不具信息价值的英文标签。课程卡片只承担课程发现；章节与课时使用连续目录而不是卡片套卡片。按钮主次稳定，加入、继续学习、保存草稿和发布分别使用一致的行动语义。

## 验收标准

- 普通用户能从课程广场打开公开课程预览，在加入前查看完整目录概要；加入后可正常进入第一课。
- 未加入用户调用课时详情、私有媒体和直播入口仍被服务端拒绝。
- 学员从课程首页可以无歧义地区分继续学习与课程发现，进度准确，课程和课时导航可往返。
- 管理员能保存不完整草稿、按步骤完善课程、按目录排序直播/录播/资料，并在发布失败时定位缺项。
- 服务端拒绝空课程、无有效内容课时和未安排直播的课程发布；有效课程可以发布或归档。
- 历史课程及直播房间、直播权限、录制和回放行为保持兼容。
- 桌面端与窄屏端均无重叠、不可达操作或横向溢出；交互状态包括加载、空列表、错误、保存中、成功和权限拒绝。

## 验证范围

API 测试覆盖公开预览字段与拒绝路径、草稿和名单可见性、发布规则、现有成员授权、媒体与直播资源隔离及历史数据兼容。前端测试覆盖课程列表状态切换、公开预览到加入、编辑步骤及验证反馈。使用真实浏览器检查桌面和窄屏的课程首页、公开预览、学习工作区和课程编辑器，并验证关键导航及进度交互。

## 不在本次范围

本次不引入支付、测验、证书、公开评论、复杂推荐算法、全局教师角色或新的直播媒体基础设施。现有直播课次与录播的技术实现不重写。
