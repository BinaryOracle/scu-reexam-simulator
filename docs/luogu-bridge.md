# 洛谷提交桥接

## 协议依据

2026-11-14 核对洛谷官方前端 `loader.20261113-2335.js`、`vendor.20261113-2335.js` 及其题目页模块，公开配置 `https://www.luogu.com.cn/_lfe/config` 的版本为 `74d532c6c7861bfe`。当前网页提交路径为 `/fe/api/problem/submit/{pid}`，图形验证码路径为 `/api/verify/captcha`。请求字段为 `code`、`lang`、`enableO2`，有验证码答案时增加 `captcha`；使用本题页面 CSRF 令牌和浏览器原会话，成功响应的提交编号为顶层 `rid`。

当前工作区语言与洛谷编号对应为：C++11 → 4，C → 2，Python 3 → 7，Java 8 → 8，Go → 14。旧编号 1、3、6、7、10 分别对应 Pascal、C++98、Python 2、Python 3、Shell，不能沿用。

## 验证与结果

插件提交后，仅在洛谷明确拒绝验证码且未要求交互验证时读取图形验证码；图片不缓存，限制为 100 KB 内的 PNG、JPEG、GIF 或 WebP。本站弹窗由用户手动输入答案，扩展携带原代码、原语言重试；错误答案显示新图片，取消则结束该次操作。图片、答案、Cookie 和 CSRF 令牌不上传至本站后端。滑块等交互验证交由洛谷原生页面处理，不尝试绕过。

无法解析成功响应或网络中断时，不自动重复提交，防止远端已受理却产生重复记录。获得有效提交编号后，扩展轮询远端记录并回传状态；若洛谷仍排队，本站保持待评测状态。网络异常、图片不可用和取消验证分别给出可操作提示。回传结果由浏览器提供，不能当作服务器独立认证的正式成绩。

## VJ 参考

用户提供的 [virtual-judge 公开仓库](https://github.com/hnshhslsh/virtual-judge) 使用按 OJ 分开的登录器、提交器、语言映射和结果查询器，通过远端账号 HTTP 会话模拟站点提交流程。`CanonicalSubmitter.java` 在提交前后查询远端最大记录编号，以确认是否产生新提交。这个公开版本的 `RemoteOj.java` 未包含洛谷，因此它能说明适配架构，不能证明当前线上 VJ 如何处理洛谷验证码。

当前 VJ 官方的[题目管理说明](https://vjudge.net/article/21922)也区分站点内置账号、个人绑定账号、题目所有者贡献的账号池；不能根据“用户没有看到验证”推断远端永远不要求验证。

本系统保留用户浏览器内的账号会话，按洛谷当前页面协议适配。正式的 OpenApp Token 评测接口属于另一种接入方式，不会因为完成浏览器桥接而自动获得其授权。

## 升级和复测

扩展最低版本为 1.1.5。更新已解压目录后，在扩展管理页点击重新加载，再刷新知序页面，清除旧内容脚本的失效上下文。下载接口 `/api/luogu-extension` 会按当前文件实时生成 ZIP，不需要手动重新打包。新版本复用已登录洛谷标签页，不会为提交自动打开或激活原题页。

本地回归：`node --test tests/luogu_extension_bridge.test.mjs tests/luogu_submit_error.test.mjs tests/luogu_submit_flow.test.mjs`；服务端桥接与压缩包：`.venv/bin/python -m pytest -q tests/test_system.py -k 'luogu or remote_result'`。这些测试覆盖请求、语言、验证码分流、取消、重试、编号解析、逐测试点结果回传和不自动导航，不替代真实平台评测。
